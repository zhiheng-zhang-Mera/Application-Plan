# Referee Control Center

> 目标：把推荐信流程做成“低摩擦、低记忆负担”的可复用模块。
>
> 核心规则：**只记录推荐人真实知道的内容；新项目只作为“上次联系后新增信息”介绍，不倒推成他们曾经了解或指导过。**

## 三条硬规则

1. **Known ≠ inferred**：不能因为项目现在很重要，就写成老师过去已经知道。
2. **Independent ≠ supervised**：Boss、DS-Hns、Quant 等课后独立项目不能包装成推荐人指导项目。
3. **Draft ≠ submitted letter**：Ting 的旧文件只代表“提供给她 review 的 draft”；不知道她最终使用了多少，因此禁止标记为 final / submitted。

## 使用方式

申请新学校时只做三件事：

1. 查看对应推荐人的 `known-to-referee.md`，确认什么可以当作既有背景；
2. 从 `new-since-last-contact.md` 选 2–4 条真正值得告诉老师的更新；
3. 按该推荐人的既有协作习惯发请求，不强行统一流程。
