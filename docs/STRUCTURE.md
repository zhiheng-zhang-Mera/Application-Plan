# Repository Structure

The repository is intentionally split into a **small control surface** and deeper evidence/history.

## Open these first

- `README.md` — lazy dashboard: current priorities, deadlines, blockers, next actions
- `rules/SCREENING.md` — the single screening / research-priority rulebook
- `rules/EXECUTION.md` — the single outreach / materials / QA / submission rulebook

## State and evidence

- `data/` — machine-readable program, supervisor and application state
- `targets/` — filtered or dated target views
- `applications/` — actual application/contact workflows and history
- `materials/` — reusable research/application source material
- `Documents/` — source academic documents and derived structured score files
- `CV-generate/` — tailored CV sources/PDFs and build inputs
- `archive/` — historical material only
- `docs/` — design/history documentation, not current policy

## Precedence

Current official evidence and confirmed application/contact events override stale snapshots.

For ordinary use, do not browse the archive or dated target files unless the dashboard links to them for a specific decision.
