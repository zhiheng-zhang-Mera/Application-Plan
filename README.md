### 手动发送固定流程

1. 从上表复制邮箱。
2. 点 **邮件正文**，复制对应的完整个性化正文和 subject。
3. 按该行 **附件 / 辅助材料** 检查材料。
4. 在邮箱里手动发送；**不要 CC/BCC 群发**。
5. 回本页更新：`最近联系日期`、`联系次数`、`状态`、`下一步 / cooldown`。
6. 如果导师明确没名额 / 拒绝，可立刻解锁同校下一位；如果出现兴趣、面试、supervision discussion，冻结该校/同系其余 cold outreach。

## ⏱️ 同校 / 同系 cooldown 规则

- 默认 **同一 `university + department` 同时只保持 1 个新 cold contact 在前台**。
- 一般等待 **约 72 小时 / 3–5 个工作日**再切同系下一位；临近 deadline 的项目可以缩短，但仍不要同一天连发多人。
- **明确拒绝 / 无名额**：可立即解锁下一位。
- **有兴趣 / 要材料 / 面试 / supervision discussion**：冻结同校同系其他 cold outreach。
- 已有线程的 follow-up（如 Zhijie）优先视为 live lead，不与同校新 cold email 并行轰炸。

## 筛选与自动化后台

人工日常操作优先停留在本 README；只有需要查为什么某人被筛掉、为什么某校不能发，才进入下面这些后台页面：

- [ACTIVE](targets/ACTIVE.md) — 可推进项目
- [WATCHLIST](targets/WATCHLIST.md) — 有门禁未清
- [BACKUP](targets/BACKUP.md) — 研究 fit 可，但流程摩擦高
- [PRUNED](targets/PRUNED.md) — 当前不值得投入
- [REJECTED](targets/REJECTED.md) — 硬门禁失败
- [screening schema](automation/screening-schema.md)
- [outreach policy](automation/outreach-policy.md)
- [auto application spec](automation/auto-application-spec.md)

**候选状态优先级仍然是：**

`REJECTED > PRUNED > BACKUP > WATCH > ACTIVE`

但对于“**我到底有没有给这个导师发过、什么时候发、对方怎么回**”，以本 README 的人工台账和对应 `applications/*/CONTACTS|TIMELINE` 为准；旧 YAML 不得把已联系导师重新当成 `not_contacted`。
